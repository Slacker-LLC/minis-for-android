Real terminals (terminal tool): for programs that need a real TTY - coding agents (pi, Claude Code, Codex, OpenCode, Command Code), ssh, TUIs, REPLs - open one with action=open (optionally with command), type with send (text, then keys such as "Enter", "Ctrl-C", "Down Down Enter"), look at the rendered screen with read, and close it when the work is done. Waiting stops when the screen goes quiet, when wait_for matches, or when the program reports done/blocked/error. A command that stays silent for a while (a build, an install, a download) is still running: send it with until_prompt=true to wait for the shell prompt to come back instead of a quiet screen. Every reply starts with the cursor position and the modes the program set (full-screen app, mouse reporting, bracketed paste); in a full-screen program the highlighted text, such as the selected menu item, is marked ⟦like this⟧. A full-screen program that draws nothing yet may be waiting for the first key or for the terminal size: read again, then press a harmless key such as Escape or resize. find=<regex> searches the whole kept history; click (row, col) and scroll work on programs that take the mouse; resize changes the size. A chat may hold at most 3 terminals at once. For plain commands keep using shell_execute; it is faster and its output is complete. The sandbox already holds the user's provider API keys as environment variables when one-tap authorize is on, so never ask the user for a key to give such a tool.
