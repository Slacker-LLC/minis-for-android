# 02 — 硬限制

违反任一条都视为错误，不能用「先跑起来」绕过。

## Fail-closed

下列任一不满足时必须失败关闭，禁止静默降级：

- 身份、策略、路径包含、签名、checksum、凭证
- 持久化真源不是合同路径，或位于 tmpfs
- Release 没有完整 `RELEASE_*` 签名材料（禁止回退 debug 密钥）
- 安全存储初始化失败（禁止把密钥改存明文）

## Root 与特权

- 新 Root 执行只允许经 `minisd` 结构化方法。
- 禁止新增「把模型输出拼进 `su -c`」的通道。
- 运行时策略只能收紧编译期能力集，不能扩大。
- 禁止为了兼容全局关闭 SELinux。
- 无障碍、悬浮窗、默认助手、通知监听、装未知应用，必须是用户/系统单独授权，不能由 Agent 自行打开「完全访问」。

## 路径

- Guest 路径拒绝 `..`、NUL、符号链接逃逸、跳出约定根。
- SAF 授权目录与 `/data/adb/minis` 是不同信任域，禁止当成同一条 POSIX 路径。
- 工具输出必须有界或溢写到受控存储。

## 网络

- 云 Provider、OAuth、更新元数据、带凭证请求走 HTTPS。
- 禁止把「任意公网明文 HTTP」当成隐式回退。
- 带凭证的重定向禁止 HTTPS → HTTP 降级。
- 本地 MCP Server 默认 loopback，需要 bearer；禁止把任意 root shell 暴露给远程调用方。

## 构建与发布

- 仓库 source-first，不承诺 GitHub Release 对应 `versionName`。
- 禁止把 APK/AAB、密钥、OAuth 机密提交进 Git。
- 缺失的构建期 Provider 定制必须表现为显式不可用，而不是进到流程里才炸。

## 进程死亡

副作用操作必须能区分：未开始 / 干净失败 / 已完成 / 结果未知。未知结果禁止盲目重试。
