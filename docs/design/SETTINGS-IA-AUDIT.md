# 设置信息架构审计（重复与重叠）

用户反馈：设置里有很多重复的东西，不只是界面。这份文档记录 2026-10-01 对设置页面树做的核对：哪些已经合并/删除，哪些仍有重叠、需要决定怎么合。**已做的项以代码为准**，“待决定”是没有动的。

## 已处理

| 重复 | 处理 |
|---|---|
| 模型首页的「思考规则」列表页与各服务商详情里的思考规则重复 | 删除入口和列表页；规则只在服务商详情里编辑（设计稿有这一项，按用户要求删） |
| 运行环境页的「终端」「浏览文件」与会话抽屉里的终端、文件重复 | 运行环境页只留 Rootfs 与环境变量 |

## 待决定（没有动）

1. **「系统增强」「系统授权」「特权后端」三块范围交叠。**
   - 系统增强：Root 状态、无障碍保活状态、LSPosed 模块开关（手势 / 双指 / 热词）、助手目标。
   - 系统授权：无障碍、助手角色、悬浮窗、受限设置。
   - 特权后端：Shizuku 安装与授权。
   - Root 状态在「就绪检查」里也有；无障碍在系统增强里只是一个跳到系统授权的行。
   - 建议：Root 状态并入「特权后端」（改名「Root 与 Shizuku」）；「系统增强」只留 LSPosed 模块开关，改名「模块」，并放进「高级」。需要确认是否这样合并。
2. **技能、记忆各有两个入口**：Agent 分类里一个，文件页「沙箱内的目录」里一个（打开的是同一个管理页）。设计稿两处都有；如果要去重，建议保留 Agent，文件页只保留「共享」（直接进文件浏览）。
3. **团队、定时任务各有两个入口**：Agent 分类和会话抽屉，打开的是同一个页面。这是用户之前要求的（设置里应涵盖所有设置项）。
4. **日志页内含「配置变更」**（分段切换），设计稿是单页加入口行。
5. **三个「权限」概念并存**：就绪检查（汇总）、系统授权（系统层授权）、工具权限（Agent 策略）。名称相近，建议把「工具权限」改名为「Agent 权限」，并在页面副标题里说明它管什么。
