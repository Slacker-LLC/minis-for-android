## 产品行为

用户唤醒 Minis 后，可以继续与当前 Bot 交流，或明确指定一位成员。口头请求绑定实际会话与任务负责人；负责人使用自己的职责、模型和工作资料接下任务，必要时委派。挂断只结束语音连接，任务继续；用户再次回来可以听取结果、补充条件或明确停止任务。

一个具体例子：用户对“资料助手”说“整理这个文件夹，做一份摘要”；它接下任务后，用户点击“补充指令”说“只整理最近一个月的”。原任务在下一步读取补充。用户退出语音继续使用手机，工作完成后得到一个结果入口；再次唤醒可询问“刚才那个任务做得怎样”。代码编译和文件处理留在同一执行链，不用维持录音才能工作。

## 本轮已实现

- 聊天声波按钮、语音快捷方式、系统助理进入 `VoiceConversationHost`，经页面投影复用当前 AgentSession、当前模型与完整工具。
- Bot 资料页增加“语音对话”，经 `BotRepository.openConversation` 打开原有直聊；显示真实 Bot 名字和头像。不是另建一个只有 Bot 名字的语音模型会话。
- 在当前会话已有任务时，语音文字进入既有 STEER 队列；不读取或清空用户文字输入框的未发送附件。
- “补充指令”结束这次结果等待/播报并重新聆听，保留 Agent 工作；“打断并说话”明确停止本通话拥有的回合。两者不会取消其它入口拥有的任务。
- 静音、挂断、后台暂停不改变任务负责人、会话和工具权限。结果和工具调用仍保存在聊天记录中。

本轮只是会话内的融合：STEER 队列目前仍为 AgentSession 内存状态；尚没有所有输入都先持久化的用户 mailbox。挂断保留的是已接受的回合，不保证 Android 进程被杀后自动恢复正在执行的命令。Bot 在其它任务 session 持锁时，当前直聊经 `agent/AgentSessionOperations.kt` 的 `withBotTurnLock` 进入 `BotTurnLockRegistry.withLock`，协程挂起等待锁释放，不立即返回忙；新语音仍属于当前直聊，不自动补充到另一项任务。委派 Dispatcher 使用 `tryAcquireExternal`，目标忙时沿既有 WAITING_TARGET/重试规则处理；锁等待不等于已建立持久用户排队。

## 下一步按顺序建设

以下是总体路线 M5 的交互细节与 M2/M4 的相关需求，**不作为独立于 Minis 重整的优先开发顺序**。2026-10-12 用户明确回归整体主线；当前 [M1 执行核心](AGENT-CORE-EXECUTION.md) 迁移及受控验收已落地，持久任务、共享工具管线和工作现场也已有切片。依 [总体路线](AGENT-ROADMAP.md) 先推进任务未知动作的独立核验和执行结果统一，再补现场/产物交付及 Bot/语音恢复；不重复从 M1 开工，整体仍未完成。

### 1. 唤醒后找回对象和任务

先加明确的用户默认接待 Bot，并记录最近交互对象。系统助理入口优先恢复用户选择的会话/任务，冷启动也能找回绑定；当前实现的系统唤醒仍创建普通新语音草稿。

在语音页显示负责人、当前工作和是否正在排队。显式选 Bot 后复用它的直聊；“让代码助手检查一下”可由当前负责人委派，保持一个根任务。成员名不明确或同名时先澄清，不自行模糊路由。

验收：相同语音请求只送给选定 Bot，退出重开后仍能定位同一 task/session；禁用或删除成员后不误送。

### 2. 先持久接单，再反馈已接收

文字、语音、例程与派工共用领取规则。保留现有 BotTask、BotDelegation、BotInboxEvent 的不同职责：根任务承载目标与验收，成员工作承载委派，inbox 承载事件，不能把其中一个表当作万能消息队列。普通用户待发送指令的持久化目前没有对应表；实施时先核对能否沿现有 session/event 存储扩展，再决定最小迁移。

每个接单带稳定请求身份；事务完成才说“已接下”，重试不能派两次。忙时清楚显示排队或补充到哪个任务；取消录音不能删除已接受任务；进程重启将未确定完成的工作交给原负责人核查，而不是重跑有副作用的命令。

验收：提交/领取/重启三个位置中断都不丢单、不重复执行；取消只影响指定请求；语音补充不带走文字草稿附件。

### 3. 统一结果简报与语音控制

当前回合完成、成员回执和需要用户决定都是不同事件。沿持久回执与 inbox 生成一份按任务聚合的短简报：完成了什么、产物在哪里、还缺哪个决定。不要朗读全部内部工具日志，也不要把子代理退出或回合停止称为交付完成。

只在活跃语音会话允许的音频时隙播报有意义的更新；忙于录音时不抢麦，锁屏/静音时保留未读入口。按持久事件身份去重，用户再问才展开细节。音频播放是否读过应与 Bot inbox 的“已消费/已唤醒”分开，否则播报会抢走 Agent 的工作事件。

明确的“停止当前任务”“继续刚才的任务”“暂停播报”“再说一遍”绑定目标 task/turn/utterance。取消任务、取消录音、停止播报需要不同动作；目标不明确时展示选择，不对所有 Bot 广播停止。

验收：多成员短时间完成只播报一份合并简报；重连不重复朗读；语音控制不会取消别人的任务；权限问题使用现有确认面板。

### 4. 优化自然对话

在上述任务与所有权稳定后，评估原生实时音频、低延迟分句播报、回声消除与说话自动打断。一个独立的音频会话生命周期可以服务多个持久任务，仍共享模型配置、权限与执行核心。先保住“我说的话已接下、任务没有被挂断误杀”，再做声音品质与全双工。

验收需要真实 Root 手机：OEM 长按电源键、锁屏到前台、蓝牙路由、扬声器回声、麦克风权限变更及前后台切换。模拟音频端口和 Android 模拟器不能替代这些证据。
