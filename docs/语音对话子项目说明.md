# Minis for Android 语音对话子项目说明

更新时间：2026-08-24

## 1. 子项目定位

本子项目是主工程 `app/` 中的语音能力集合，负责：

```text
麦克风采集 → ASR 转文字 → 调用大模型 → 得到回答 → TTS 合成 → 播放
```

它已经被桌面宠物语音入口和聊天页语音输入使用。它不是独立 APK，也不包含新的通话 UI。

## 3. ASR 选择机制

`ProviderRepository` 解析 Voice Input group：

- 系统 sentinel：使用 `SystemSpeechRecognitionEngine`；
- Provider 模型：使用 `ProviderSpeechRecognitionEngine`；
- Provider ASR 没有 partial result，通常在一段录音结束后一次性返回；
- 系统 ASR 支持 partial result，但通话 MVP 应以 final result 触发模型请求；
- `SpeechRecognitionManager` 负责统一暴露 `STARTING`、`RECORDING`、`FINISHING`、`IDLE`。

打开麦克风前必须已经获得 `RECORD_AUDIO` 权限。ASR 管理器在开始录音时会暂停正在播放的朗读，避免扬声器回声被重新识别。

## 4. 大模型路径

### 当前桌面宠物路径

`PetChatEngine`：

- 直接使用当前默认模型和 Provider；
- 保留最近少量上下文；
- 要求回答短、无 Markdown，适合语音和桌面气泡；
- 会把用户和助手消息写入“桌面宠物”会话；
- 不运行完整 Agent 工具链。

### 聊天页路径

`ChatViewModel` 负责完整聊天会话和 Agent Loop，包含流式内容、工具调用和消息持久化。它依赖 Compose 页面和会话生命周期，不建议直接注入新的通话 Runtime。

语音通话第一阶段应通过 `CallModelGateway` 包装 `PetChatEngine`，先完成稳定的端到端闭环；需要完整 Agent 能力时，再增加独立的 Headless/Agent Gateway。

## 5. TTS 路径

`ReadAloudPlayer.speakConversation(text)` 是语音对话专用入口：

1. 根据 Voice Output group 解析系统 TTS 或在线 Provider；
2. 在线 Provider 调用 `VoiceProvider.synthesize()` 返回音频字节；
3. 写入缓存文件，通过 `MediaPlayer` 播放；
4. 在线请求或播放失败时回退 `TextToSpeechManager`；
5. 当前入口是异步排队式 API，需要为通话 Runtime 增加可靠的“播放完成”通知。

注意：通话专用的 `speakConversation()` 不应依赖用户是否打开聊天页的“朗读回复”开关，但仍应尊重临时静音和录音期间的回声保护。

## 6. 当前已实现入口

`PetOverlayService` 的实际流程是：

```text
点击桌面宠物语音
 → 解析 Voice Input
 → 开始 ASR
 → final text
 → PetChatEngine.ask
 → ReadAloudPlayer.speakConversation
```

当前限制：

- 一轮播放结束后不会自动重新开始 ASR；
- 不是完整 `LISTENING → THINKING → SPEAKING → LISTENING` 通话循环；
- 真语音打断和扬声器回声消除尚未做；
- Provider TTS 已存在，但是否使用取决于 Voice Output group 配置。

## 7. 给语音通话 Runtime 的推荐接口

通话模块不要直接依赖上述所有实现，建议包三层端口：

```kotlin
interface CallSpeechInput {
    fun start(onPartial: (String) -> Unit, onFinal: (String) -> Unit,
              onError: (RecognitionError, String?) -> Unit)
    fun stop()
    fun cancel()
}

interface CallModelGateway {
    suspend fun ask(text: String): Result<String>
    fun cancel()
}

interface CallSpeechOutput {
    suspend fun speak(text: String)
    fun stop()
}
```

生产实现包装现有类，测试使用 Fake。这样通话状态机测试不需要真实麦克风、网络和音频设备。

## 8. 验收重点

- 系统 ASR 可用时，不配置云端 ASR 也能进入通话；
- 配置 Voice Input Provider 后，可以切换到云端 ASR；
- 配置 Voice Output Provider 后，实际请求在线 TTS 并播放；
- 在线 TTS 失败时能记录原因并按约定回退系统 TTS；
- 录音期间不会播放旧的 TTS 音频；
- 结束录音、取消录音和挂断后没有残留回调或协程。
